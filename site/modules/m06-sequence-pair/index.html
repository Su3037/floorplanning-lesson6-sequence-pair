01 / 目标与问题

这一模块要解决什么

先看问题和成功标准，再看算法。每个目标后面的链接指向讲它的地方。

复习前面的课程用切分树（Polish 表达式）和 B*-tree 表示布图；它们各自有能表示与不能表示的摆放。本课的序列对只用两个排列，能表示任意不重叠的摆放，而且任何两个排列都给出一个不重叠的摆放。全课用教师的五块例子：A 3×2、B 2×3、C 2×2、D 3×1、E 2×2，固定边界 10 × 8。

学习目标

  1. 说出布图规划的输入、输出和约束，解释为什么直接搜索坐标很麻烦、为什么要用表示法。布图规划要解决什么
  2. 由 pos 与 neg 读出任意两块的相对位置（四种情况），并找出不合法序列对里的全部问题。两个排列，四种关系 · [推演] 读出相对位置 · [纠错] 诊断不合法的序列对
  3. 把关系变成水平 / 竖直约束图，写出每条边的不等式，说明约束图为什么没有环。从关系到约束图 · [构图] 谁指向 E，谁指向 D
  4. 用最长路径动态规划算出每块的坐标，解释为什么加前驱的尺寸、为什么取最大。最长路径：为什么加前驱的宽，为什么取最大 · [推演] 算一个坐标 · [实现] 写出整张布局
  5. 把完整、不重叠、装得下、紧凑四个问题分开回答，分清不随排列变化的量与会变化的量。合法、装得下、紧凑：分开看 · [约束] 造一个合法却装不下的序列对
  6. 推理改动排列对几何的影响（包括“不同写法、同一布局”），并在 Python 中实现校验、建图、DP 与指标。改一个排列会怎样 · 逐行读懂伪代码 · [比较] 换一种写法，同一张布局 · Python

问题定义

输入

若干矩形块（固定宽 w、高 h，不旋转）；固定边界 W × H；两个排列 pos 与 neg。

输出

每块左下角坐标 (x, y)；水平约束图 H 与竖直约束图 V；完整性、重叠、是否装得下；包围盒与面积指标。

目标

用两个排列表示块之间的相对位置，并求出满足全部相对位置的最紧凑（最小）坐标。

约束

pos 与 neg 必须是同一组块的排列；每对块恰好一种关系；H 边 i→j 要求 x[j] ≥ x[i] + w[i]，V 边 i→j 要求 y[j] ≥ y[i] + h[i]。

假设

原点在左下角、y 向上；“pos 中在前、neg 中也在前 → 左边”，“pos 中在前、neg 中在后 → 下边”（教师约定）；贴边允许，正面积相交才算重叠。

停止 / 完成

两遍动态规划（x 一遍、y 一遍，各 n 步）都完成后输出；输入不合法时在第一步列出全部问题并停止。

§ 1布图规划要解决什么

一块芯片在动手画晶体管之前，先要决定大块的东西放在哪里：处理器核、缓存、接口、模拟电路……每一块都是一个矩形，宽和高大致已知。把这些矩形摆进芯片给定的轮廓里，不重叠、尽量紧凑、相关的块离得近——这一步叫布图规划（floorplanning）。它发生在详细布局（placement）和布线（routing）之前，决定的是“版图的骨架”。

模块 / 块

module / block

布图规划里的一个矩形单元，有固定的宽 w 与高 h。本课的例子有 A–E 五块。

布图

floorplan

给每一块一个位置（本课用左下角坐标 x、y）后得到的整体摆放。

固定边界

fixed outline

芯片留给这些块的矩形区域，宽 W、高 H。本课的例子是 10 × 8。

本课自始至终用教师课程的五块例子（examples/tiny_modules.json）：

块宽 w高 h面积
A326
B236
C224
D313
E224
合计23

固定边界 10 × 8，面积 80。块的总面积只有 23，看起来空间绰绰有余——后面会看到，“面积够”并不等于“装得下”。

为什么不直接搜坐标？ 最直接的描述是给每块写下 (x, y)：五块就是十个数。可是要在电脑里搜索好的布图时，坐标是一种很难用的表示：

  1. 随便改一个数，块就可能压到别的块上。绝大多数坐标组合都是重叠的，搜索要花大量时间在不合法的状态里。
  2. 坐标是连续的，同一种“谁在谁左边”的摆法对应无穷多组坐标，大部分只是平移了一点点。
  3. 真正影响结果的往往是相对次序（谁挨着谁、谁在上面），而坐标把它藏起来了。

布图规划算法因此常用一种表示法（representation）：用离散的结构记录相对位置，再用一个确定的程序把它变成坐标。前面的课程里有切分树（Polish 表达式）和 B*-tree；这一课的序列对（sequence pair）由 Murata、Fujiyoshi、Nakatake、Kajitani 在 1995–1996 年提出，只用两个排列，就能描述任意块之间的上下左右关系，而且任何两个排列都对应一个不重叠的摆放。

这是教学用的小例子

本课的程序只处理几块到十几块的矩形，用来看清表示法与约束推导。真实芯片的布图还要考虑连线长度、时序、电源、引脚、模块形状可变、不同层的阻挡等，详细布局、布线和签核要交给专门的 EDA 工具。这里讲的是其中一个核心想法，不是生产流程。

§ 2两个排列，四种关系

排列

permutation

把同一组块各写一次、排成一行。五块有 5! = 120 种排列。

相对次序

relative order

在一个排列里，a 是在 b 前面还是后面。只关心先后，不关心隔了几个。

序列对

sequence pair

两个排列 (pos, neg)，也写作 Γ+、Γ−。两者必须是同一组块。

序列对里每一对块 (a, b) 都有两个“先后”：在 pos 里谁在前、在 neg 里谁在前。两个先后组合起来恰好有四种情况，对应四种相对位置：

pos 中neg 中关系约束
a 在 b 前a 在 b 前a 在 b 左边x[b] ≥ x[a] + w[a]
a 在 b 后a 在 b 后a 在 b 右边x[a] ≥ x[b] + w[b]
a 在 b 前a 在 b 后a 在 b 下边y[b] ≥ y[a] + h[a]
a 在 b 后a 在 b 前a 在 b 上边y[a] ≥ y[b] + h[b]

一句话记法：两个序列里次序相同 → 左右；次序相反 → 上下。哪一个在左，看两个序列里都在前的那个；哪一个在下，看 pos 里在前的那个。

本课的坐标约定（与教师实现 common/pack.py 一致）：原点在左下角，x 向右增大，y 向上增大。屏幕上的 SVG 和画布 y 是向下的；本页的图在绘制时把 y 翻转过来，但规则和坐标都按“y 向上”计算，不偷偷改规则。

另一种约定

有些教材和论文把第三行写成“pos 中在前、neg 中在后 → 上边”。两种约定都自洽，只是竖直方向镜像。测试证明：在那种约定下的 (pos, neg)，与本课约定下的 (neg, pos) 得到完全相同的坐标。读别的资料时先看它用哪一种，再决定要不要交换两个序列。

最小的例子只有两块。A 是 3 × 2，B 是 2 × 3：

  • pos = A B，neg = A B：两个序列里 A 都在前 → A 在 B 左边，B 从 x = 3 开始。
  • pos = A B，neg = B A：次序相反，pos 里 A 在前 → A 在 B 下边，B 从 y = 2 开始。

有 n 块就有 n(n − 1)/2 对，每一对恰好落在四种情况中的一种。所以序列对不会出现“这一对没说清楚”或“这一对既在左又在上”的情况——这是它比坐标好用的根本原因之一。

合法的序列对：pos 和 neg 都必须是同一组块的排列。常见错误有四种，引擎会把它们全部列出，而不是只报第一个：

错误例子报错
缺块pos = A B C Epos 缺少 D；两序列长度不同
重复neg = D A B C Aneg 里 A 出现 2 次；neg 缺少 E
未知块pos = A B C E Zpos 里有未知模块 Z；pos 缺少 D
长度不同pos 4 项、neg 5 项长度不一致

§ 3从关系到约束图

约束图

constraint graph

节点是块，有向边 i → j 表示一条“j 必须让开 i”的不等式。

水平约束图 H

horizontal graph

i 在 j 左边时连 i → j，边上的不等式是 x[j] ≥ x[i] + w[i]。

竖直约束图 V

vertical graph

i 在 j 下边时连 i → j，边上的不等式是 y[j] ≥ y[i] + h[i]。

有向无环图

DAG

有向图里沿着箭头走永远回不到起点。约束图必须是 DAG，否则不等式无解。

把每一对块的关系写成一条边，就得到两张图：左右关系进 H，上下关系进 V。每一对块只进其中一张图，所以两张图的边数加起来正好是 n(n − 1)/2。

以教师的示例 pos = A B C E D，neg = D A B C E 为例，十对块的关系如下（按 pos 中的位置列出 a、b）：

块对pos 中neg 中关系边
A, BA 前A 前A 在 B 左边H：A → B
A, CA 前A 前A 在 C 左边H：A → C
A, EA 前A 前A 在 E 左边H：A → E
A, DA 前A 后A 在 D 下边V：A → D
B, CB 前B 前B 在 C 左边H：B → C
B, EB 前B 前B 在 E 左边H：B → E
B, DB 前B 后B 在 D 下边V：B → D
C, EC 前C 前C 在 E 左边H：C → E
C, DC 前C 后C 在 D 下边V：C → D
E, DE 前E 后E 在 D 下边V：E → D

H 有 6 条边，V 有 4 条：A、B、C、E 从左到右排成一行，D 在它们所有块的上面。

有些边是“推出来的”。A → E 这条边可以由 A → B → C → E 推出：只要 B 让开 A、C 让开 B、E 让开 C，E 自然让开 A。图里把这类边画成虚线。它们并不多余到可以删掉的程度——算坐标时把所有边都考虑进去最简单，也不会算错；只是看图时虚线不抢眼。

为什么约束图一定没有环？ 每条边 i → j（不论 H 还是 V）都要求 i 在 pos 中排在 j 前面：左边关系要求“两个序列里都在前”，下边关系要求“pos 中在前”。沿着箭头走，pos 中的位置只增不减，所以永远回不到起点。这也给了我们一个现成的处理顺序：按 pos 的顺序处理每一块，处理到 j 时，它所有的前驱都已经处理过了。这样的顺序叫拓扑序。

§ 4最长路径：为什么加前驱的宽，为什么取最大

最长路径

longest path

在 DAG 里，从任意源点走到 j 的路径中，边权之和最大的那条的长度。

压紧

compaction

每块都放在满足所有约束的最小坐标上：能往左（往下）挪就挪到不能再挪为止。

现在每块都有一组不等式要满足。例如 E 的水平前驱是 A、B、C：

  • x[E] ≥ x[A] + w[A]
  • x[E] ≥ x[B] + w[B]
  • x[E] ≥ x[C] + w[C]
  • 以及 x[E] ≥ 0（不能出左边界）

为什么加的是前驱的宽，而不是 E 自己的宽？ 边 i → j 说的是“j 的左边缘不能越过 i 的右边缘”。i 的右边缘在 x[i] + w[i]——所以加的是 i 的宽。E 自己的宽决定的是 E 的右边缘，和这条不等式无关。

为什么取最大？ 每一条不等式都必须成立，所以 x[E] 至少要大于所有右边的值；能满足全部不等式的最小值就是它们中的最大值。取最小只满足了其中一条。

先看三块的例子：A 3 × 2、C 2 × 2、B 2 × 3，pos = A C B，neg = C A B。A 在 C 下边，A、C 都在 B 左边。

块水平前驱候选值x
A—00
C—00
BA、CA：0 + 3 = 3；C：0 + 2 = 23

如果取最小值 2，B 会从 x = 2 开始，压在 A 的右上角上（A 占 x 0–3、y 0–2）——这正是右图红色的那一块重叠。

把每块都这样处理一遍，就是按拓扑序的动态规划：

  • x[j] = max(0, 所有 H 边 i→j 上的 x[i] + w[i])
  • y[j] = max(0, 所有 V 边 i→j 上的 y[i] + h[i])

这个值等于 H（或 V）里到 j 的最长路径长度（边 i → j 的权是 w[i] 或 h[i]）。它是满足全部约束的最小坐标，所以得到的布图是压紧的：每一块都不能再往左或往下挪。

不要把两份“标准答案”混在一起

教师的 common/goldens.py 里还有一份 GOLDEN_PACK，其中 D 在 (0, 2)。那是另一份单独画的示意摆放，不是这个序列对算出来的结果。按序列对的规则，D 在 B 上方，而 B 高 3，所以 D 只能从 y = 3 开始。

代价。 列出所有块对是 n(n − 1)/2 步；动态规划每块要看它所有的前驱，总共也是 O(n²)。本课的实现就是这个 O(n²) 的版本。文献中有更快的算法（例如 Tang 与 Wong 用最长公共子序列做到 O(n log n)），本课没有实现，也不声称本课的程序有那样的复杂度。

§ 5合法、装得下、紧凑：分开看

重叠

overlap

两块的内部有正面积的交集。只是边贴边（交集面积为 0）不算重叠。

溢出

overflow

某块超出了固定边界。宽度方向溢出 max(0, 包围盒宽 − W)，高度方向同理。

包围盒

bounding box

包住所有块的最小矩形（从原点到最右、最上的边缘）。

密度

density

块总面积除以某个区域的面积。对固定边界和对包围盒，要分开说。

空余面积

deadspace

某个区域里没有被块占用的面积，同样要说清是边界还是包围盒。

教师示例算完后，要回答的其实是四个不同的问题，答案要分开报告：

问题怎么判断教师示例
完整吗？每块恰好放了一次，没有缺、没有多是（5 块）
有重叠吗？任意两块有没有正面积的交集没有（序列对保证）
装得下吗？每块都在 0 ≤ x、x + w ≤ W、0 ≤ y、y + h ≤ H 之内是：包围盒 9 × 4 在 10 × 8 之内
紧不紧？包围盒面积、包围盒利用率9 × 4 = 36，空余 13，利用率 23 / 36 ≈ 63.89 %

还有两个数常常被一起报出来：边界面积 80，块面积 23，边界空余 57，边界密度 23 / 80 = 28.75 %。要特别注意，这两个数和序列对无关：块的面积是固定的，边界也是固定的，不论你把块怎么排，它们都不变。本课的测试把全部 14,400 个序列对都算了一遍，边界空余始终是 57，密度始终是 28.75 %。所以：

  • 不要在动画里把它们画成“随着块移动而改善”；
  • 不要把“边界面积 − 块面积 ≥ 0”当成装得下的证明；这个差是负数时也不代表什么“可用的空白”。

真正会随排列变化的是包围盒的宽和高、包围盒面积与利用率、是否溢出、溢出多少。

合法 ≠ 装得下。 看这个序列对：pos = A B C D E，neg = A B C D E。两个序列完全相同，所以每一对都是“左右”关系，五块排成一行：

宽度 3 + 2 + 2 + 3 + 2 = 12，超出边界 2；高度只有 3。它没有任何重叠，是一个完全合法的序列对，可它装不下。把 neg 反过来（E D C B A），每一对都变成“上下”关系，五块叠成一列，高 2 + 3 + 2 + 1 + 2 = 10，超出边界 2。

序列对保证什么、不保证什么

它保证：每一对块都有确定的相对位置，按最长路径算出的坐标不重叠、而且压紧。它不保证：装进任意给定的边界、面积最小、或者每一种几何摆放只有一种写法。五块的 14,400 个序列对里，13,680 个装得进 10 × 8，720 个装不进。

§ 6改一个排列会怎样

布图搜索的基本动作是：对序列对做一个小改动，重新算坐标，看指标变好还是变坏。最常见的改动有三种：只在 pos 里交换两块、只在 neg 里交换两块、在两个序列里同时交换两块。

从教师示例出发，每次只交换相邻的两块，结果并不都一样：

改动posneg包围盒坐标是否改变
不改A B C E DD A B C E9 × 4—
pos 中交换 A、BB A C E DD A B C E7 × 6改变
pos 中交换 C、EA B E C DD A B C E7 × 5改变
pos 中交换 E、DA B C D ED A B C E9 × 4不变
neg 中交换 D、AA B C E DA D B C E9 × 4改变
neg 中交换 C、EA B C E DD A B E C7 × 5改变

有两点值得注意：

  1. 不同的序列对可以得到完全相同的布图。 在 pos 中交换 E、D 之后，E 与 D 的关系从“E 在 D 下边”变成了“D 在 E 左边”——关系变了，可是 D 在左上角（x 0–3），E 在右下角（x 7–9），两种关系都成立，算出来的坐标一模一样。穷举表明，五块共有 14,400 个序列对，却只有 9,056 种不同的布图；教师示例的布图恰好有 3 种写法（neg 不变，pos 中 D 放在 B 之后的三个位置都可以）。
  2. 包围盒一样，不代表布图一样。 在 neg 中交换 D、A 后包围盒仍是 9 × 4，但 A 跑到了 D 的左边，坐标变了。
同一个结论，不要说过头

“改一个排列”不一定改变所有坐标，也不一定改变任何坐标；它改变的是某些块对之间的关系。要知道几何有没有变，只能重新算。

从表示到搜索。 五块时 14,400 个序列对可以全部算一遍，最紧的包围盒是 6 × 4 = 24（例如 pos = A C D E B，neg = C E A B D），只比块面积多 1。块一多，(n!)² 个序列对就算不完了，实际的布图工具会用模拟退火之类的随机搜索：反复做上面三种小改动，按代价（包围盒面积、溢出、连线长度等）决定接不接受。下一课会讲这一步；本课的实验里有一个“随机邻居”按钮，可以先体验“改一下、重算一下”。

  3. 若 neg 中 i 也在 j 之前：加 H 边 i → j（i 在 j 左边）
  4. 否则：加 V 边 i → j（i 在 j 下边）

§ 8背景、应用与局限

来源。 序列对由 H. Murata、K. Fujiyoshi、S. Nakatake、Y. Kajitani 提出（ICCAD 1995；完整论文 VLSI Module Placement Based on Rectangle-Packing by the Sequence-Pair，IEEE TCAD 15(12), 1996）。论文证明了：任何一种不重叠的矩形摆放都能用某个序列对表示；反过来，任何序列对按约束图算出的摆放都不重叠。这让“在所有合法摆放里搜索”变成了“在 (n!)² 个排列对里搜索”。论文图片不在本课程的许可范围内，本课只引用、不转载。

应用。 序列对和 B*-tree 一样，是基于模拟退火的布图规划器常用的表示：状态是一个序列对，邻居是交换或旋转，代价函数一般综合面积、固定边界溢出与线长。固定边界版本的研究（例如 Adya 与 Markov 的 Parquet，2003）也把序列对作为核心表示之一。

局限。

  • 本课的块尺寸固定、不旋转；软模块（面积固定、长宽比可变）与旋转都会让同一个序列对对应不同的坐标。实验里的“旋转”是标明的拓展，不改变本课的标准答案。
  • 本课只讲如何把序列对变成坐标，不讲怎样找到好的序列对；那是搜索算法（下一课：模拟退火）的工作。
  • 坐标是压向左下角的；装不下时程序只报告溢出，不会自动改排列。
  • 没有连线、引脚、时序或电源模型；包围盒与溢出只是几何指标。若加入 HPWL 之类的线长，它也只是代理指标，不是布线后的真实线长。
  • O(n²) 的教学实现适合几十块以内；更大的实例要用更快的求值算法和增量更新。

概念自测

六道选择题，考的是理解而不是记住例子的字母。点选即判，可以反复改。

概念 1 布图里 A 在 B 左边，并且这是由序列对规定的关系。那么在 pos 和 neg 中……

左右关系要求两个序列里次序相同；在左边的那块在两个序列里都在前。

概念 2 固定边界面积 80，块总面积 23。下面哪句话正确？

装不装得下看包围盒的宽和高，不看面积。14,400 个序列对里有 720 个装不进 10 × 8，它们都不重叠。

概念 3 把一个序列对换成另一个，固定边界的密度（块面积 / 边界面积）会怎样？

块面积与边界面积都是固定的，比值与排列无关。会变化的是包围盒面积与利用率。

概念 4 计算 x[j] 时，为什么对所有水平前驱取最大值而不是最小值？

取最小只满足了一条不等式；三块例子里取最小会让 B 压在 A 上。

概念 5 两个不同的序列对，算出的坐标……

pos = A B C D E、neg = D A B C E 与教师示例的坐标完全相同。五块共 14,400 个序列对，只有 9,056 种不同布局。

概念 6 为什么可以直接按 pos 的顺序做动态规划？

左关系要求 pos 中在前，下关系也要求 pos 中在前；沿着任何一条边走，pos 中的位置都在增加。

07 / 在线编程 · 在浏览器里运行 Python

自己实现序列对求值

不用安装任何东西：Python 在你的浏览器里运行（Pyodide），代码只保存在本机。检查器与下载包里的 check.py 完全相同。

任务（starter.py，五个函数）：

  1. validate_pair(pos, neg, ids)：列出全部问题（缺、重、未知、长度不同）。
  2. relation(pos, neg, a, b)：返回 left / right / below / above。
  3. build_graphs(pos, neg)：返回水平边与竖直边，每对块恰好一条。
  4. longest_path(nodes, edges, size, rank)：按拓扑序做 DP，取最大、加前驱尺寸。
  5. metrics(modules, outline, placement)：完整、重叠（贴边不算）、溢出、包围盒、面积指标。

提示一：先只做两块的例子：pos = A B、neg = B A 时 A 在哪里？再推广到每一对。

提示二：DP 的每一步写成“候选 = 前驱坐标 + 前驱尺寸，取最大，再与 0 比较”。检查器会在 300 个随机序列对上验证每条边都成立、每块都压紧，并把全部 14,400 个五块序列对算一遍。

怎么用

  1. 在编辑器里补全标着 TODO 的函数。
  2. 按 运行检查（Ctrl/⌘ + Enter）：每一项给出 PASS、FAIL 或 INCOMPLETE。
  3. 全部通过后，在下方用你自己的函数跑一遍例子，逐步对照课程引擎。

08 / 常见错误与局限

容易错在哪里

每条都给错误结果、错因、反例和修正；反例的数值都由测试复算。

把规则的上下颠倒（或混用两种约定）

错误结果
认为“pos 中在前、neg 中在后”表示在上面，于是教师示例里 D 被放到最下面。
错因
本课（与教师实现）规定的是“在下面”。另一种约定在一些教材里存在，但不能在同一个程序里混用。
反例 / 证据
教师示例中 A 在 pos 第 1、neg 第 2，D 在 pos 第 5、neg 第 1：A 在 pos 中在前、neg 中在后 → A 在 D 下边，D 的 y = 3。按颠倒的规则，D 会在 y = 0，A、B、C、E 被抬到 y = 1。
修正
先写明约定。读另一种约定的资料时，把它的 (pos, neg) 交换成 (neg, pos) 再用本课的规则——测试证明两者坐标相同。

动态规划取了最小值

错误结果
x[j] = min(x[i] + w[i])，以为“离得最近的前驱”说了算。
错因
每条边都是一条必须成立的不等式；只满足最近的一条，其他前驱就会被压住。
反例 / 证据
三块例子 pos = A C B、neg = C A B：B 的候选是 0 + 3 = 3（来自 A）和 0 + 2 = 2（来自 C）。取最小得 x[B] = 2，B 与 A 重叠 1 × 2。
修正
x[j] = max(0, max over 前驱 i 的 x[i] + w[i])；y 同理。

加了自己的宽，而不是前驱的宽

错误结果
x[E] = max(x[i]) + w[E]，或者 x[i] + w[E]。
错因
边 i → j 说的是 j 的左边缘不能越过 i 的右边缘，i 的右边缘是 x[i] + w[i]。
反例 / 证据
教师示例中 B 唯一的水平前驱是 A：正确的 x[B] = 0 + 3 = 3（A 的宽）。若加 B 自己的宽，得到 0 + 2 = 2，B 与 A 重叠 1 × 2；之后 C、E 也会跟着错位。
修正
候选值永远是“前驱的坐标 + 前驱的尺寸”。实验的 DP 面板逐项列出这两个数。

把“面积够”或“不重叠”当成“装得下”

错误结果
块面积 23 ≤ 边界面积 80，所以布局合法；或者“没有重叠，所以通过”。
错因
装得下看的是每块是否在边界之内，即包围盒的宽和高；序列对只保证不重叠。
反例 / 证据
pos = neg = A B C D E：不重叠，但宽 12 > 10。pos = A B C D E、neg = E D C B A：不重叠，但高 10 > 8。14,400 个序列对里 720 个这样。
修正
分开报告：完整、不重叠、装得下、包围盒、面积指标。

以为边界空余面积会随排列改善

错误结果
做了一次交换后报告“空余面积从 57 降到了 13”。
错因
57 是边界面积减块面积，与排列无关；13 是包围盒面积减块面积，那才是会变的量。两个数说的是不同区域。
反例 / 证据
全部 14,400 个序列对的边界空余都是 57、边界密度都是 28.75 %；包围盒面积从 24 到 36 以上都有。
修正
写清楚“边界的”还是“包围盒的”；只用包围盒指标比较两种排列。

适用范围与局限

  • 块尺寸固定、不旋转；旋转与软模块是拓展，会让同一个序列对对应不同坐标。
  • 本课只把序列对变成坐标，不负责找好的序列对；搜索交给模拟退火等方法（下一课）。
  • 坐标压向左下角；装不下时只报告溢出，不会自动改排列。
  • 没有连线、引脚、时序、电源模型；包围盒与溢出只是几何指标，不是布线结果。
  • O(n²) 的教学实现适合几十块以内；文献中有 O(n log n) 的求值算法，本课没有实现。
